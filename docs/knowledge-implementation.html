업무에서 축적하고 다음 과제에서 재사용하는 조직 지식자산

과제 담당자가 별도의 지식 그래프를 관리하지 않아도, 등록·실적·첨부 과정에서 근거가 연결되어야 한다. 시스템은 후보와 초안을 준비하고, 사람은 의미와 적용 가능성을 확인한다.

목적과 성공 기준

과거에 해결한 문제를 다시 조사하는 시간을 줄이고, 실패한 접근을 반복하지 않으며, 누가 어떤 근거로 판단했는지 추적한다. 연결 개수보다 확인된 재사용, 근거를 찾는 시간, 확인 부담을 평가한다. 개인·팀의 생산성 순위는 만들지 않는다.

측정 항목이번 구현파일럿에서 확인할 것
확인한 재사용작성자가 결과 활용으로 확인하고, 인용 근거가 유효한 관계만 계산실제 적용 여부와 효과를 종료 회고에서 확인
근거 추적자동 연결의 원본 위치·버전, 첨부 해시·행 범위, 확인자·확인 시점 보존표본 관계의 인용 정확성과 원본 이동 성공률
확인 부담새 후보 최대 5개, 중복 후보 제외, 인용 내용이 바뀐 관계만 재확인후보 1건의 확인 시간과 관련 없음 비율
업무 중 재사용등록 중 문구 검색, 저장한 실적에서 지식 화면 진입, 경험 초안 빈칸 적용참고 사례를 찾는 데 걸린 시간. 조회 이벤트 계측은 후속 작업

사용자 여정

  1. 등록: 제목·배경·KPI를 작성하면 관련 문구가 있는 과거 과제를 제시한다. 같은 Tech만으로 관련성을 단정하지 않는다. 작성 내용은 유지하고, 후보 근거를 화면 안에서 확인한다.
  2. 월별 보고: 저장한 실적·지연 사유·만회 계획을 자동 근거로 연결한다. 참고 사례 화면에서 원본 보고 월로 이동한다. 미저장 실적을 저장된 사실로 취급하지 않는다.
  3. 관계 확인: 담당자가 관련 과제·결과 활용·관련 없음 중 선택한다. 추천 점수는 일치 문구의 순위이며 의미 정확도나 확률이 아니다.
  4. 경험 기록: 배경·추진 계획·실적·지연·만회 기록에서 초안을 발췌한다. 문서의 주의·적용 조건도 근거와 함께 발췌할 수 있다. 빈 항목에만 적용하며 저장과 공유는 사람이 수행한다.
  5. 재검토: 인용한 문제·방법·문서 내용이 바뀌면 관계를 확인 수치와 근거 맵에서 제외하고 당시/현재 근거를 비교한다. 무관한 월별 실적 추가는 재확인을 발생시키지 않는다.

정보를 세 가지 상태로 구분

종류생성표시·권한
등록된 사실Tech·조직 표기·PO/PM/참여자·Step·월별 실적·첨부를 자동 투영원본 기록의 사실임을 표시. 업무 효과나 원인을 추가로 추론하지 않음
미확인 후보제목·경험·실적 기록·지원 문서의 실제 문구를 검색근거와 일치 문구를 표시. 후보만으로 관계를 만들지 않음
확인한 관계기존 과제 편집 권한자가 관련성·결과 활용을 확인확인자·시점·당시 근거 보존. 변경된 근거는 재확인 전까지 제외

기존 수동 선행·후속·유사 관계는 별도로 유지한다. 수동 기록을 자동 검증된 지식으로 바꾸지 않는다. 공유된 경험 카드도 작성자 확인 상태이며 공식 성과 인증을 뜻하지 않는다.

이번 개발에 포함한 범위

  • 과제별 자동 업무 근거 맵, 근거 종류별 탐색, 원본 과제·실적 월·첨부 화면으로 이동.
  • 서버의 담당 전체 과제에서 문구 검색. 시연은 해당 브라우저의 데이터 범위. 동의어 추론·임베딩 의미 검색은 미구현.
  • 관련·결과 활용·관련 없음 확인과 변경 이력. 원본 동시 변경을 확인하는 버전 조건과 내용 토큰.
  • 기존 기록에서 경험 카드 초안 생성, 작성 내용 보존, 적용한 근거의 원본 위치·버전 저장.
  • 새 TXT·CSV 첨부의 UTF-8 본문 색인. 파일 해시와 행 범위 보존. 1MB 이하 파일, 최대 120,000자, 인용 조각 최대 4,000자.
  • 기존 첨부를 재처리하는 배치 명령. PDF·Office·이미지는 파일 메타데이터만 연결하고 본문 추출 미지원으로 표시.

데이터와 API 설계

현재 근거 맵은 원본에서 다시 계산하므로 별도의 그래프 DB가 필요 없다. 사람이 확인한 관계와 경험 카드는 PostgreSQL 과제 문서에, 문서 본문은 전용 테이블에, 변경 전후는 기존 감사 이력에 저장한다.

구성보존 내용
자동 사실 노드과제 ID·Step ID·보고 월·파일 ID. 계정·조직 ID가 없으면 과제 안의 지정 정보로만 표현하고 동명이인·조직 개편 전후를 이름으로 합치지 않음
지식 관계 확인대상 ID, 관계 유형, 확인/제외, 확인자·시점, 대상 근거와 해당 과제의 맥락 근거, 원본 버전
초안 인용경험 필드, 과제 ID, 원본 필드 위치, 인용, 기록 버전. 새 인용은 서버의 원본과 일치하는지 확인
문서 본문불변 첨부 ID·해시, 처리 상태, 제한된 본문, 잘림 여부. 문서 내용은 명령으로 실행하지 않음
  • GET /api/projects/{id}/knowledge-context 자동 근거·후보·초안·검토 상태
  • POST /api/knowledge/recommendations 작성 중인 내용으로 담당 전체 문구 검색
  • POST /api/projects/{id}/knowledge-decisions 원본 버전 조건을 적용한 관계 확인
  • PUT /api/projects/{id}/knowledge 경험 카드와 인용 저장

모든 경로는 기존 사내 인증을 적용한다. 읽기 권한과 편집 권한은 분리한다. 문서·프로젝트에 더 세밀한 열람 제한을 도입할 경우, 검색과 원본 이동에도 같은 제한을 적용해야 한다.

현재 검색은 투영된 과제와 지원 문서를 읽는 초기 구현이다. 대규모 다년 데이터의 응답 시간은 HCP에서 대표 데이터로 별도 측정해야 한다. 사내 AI 엔드포인트가 없는 상태에서 외부 AI로 데이터를 보내거나 AI 기능이 연결된 것처럼 표시하지 않는다.

검증 시나리오

  • 누적 0% 실적도 근거가 되며 미입력과 구분된다.
  • 같은 Tech만 공유하고 문제가 다른 두 과제는 자동 관련 후보가 되지 않는다.
  • 후보 확인 전에는 관계가 없고, 확인 후에만 근거 맵과 재사용 수치에 반영된다.
  • 확인 당시와 현재 근거가 달라지면 재확인 대상으로 이동한다. 무관한 보고 월 추가는 관계를 유지한다.
  • 동시 수정, 없는 대상, 위조 인용, 일반 구성원의 수정 요청이 거부되고 입력은 유지된다.
  • 이미 작성한 경험을 초안 적용으로 덮어쓰지 않는다.
  • 첨부 원문에서 검색되고 파일 ID·해시·행 범위를 추적한다. 제한·미지원 파일은 상태를 표시한다.
