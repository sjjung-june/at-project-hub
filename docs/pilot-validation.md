# 파일럿 시나리오와 검증 결과

작성일: 2026-11-24

## 판정

이번 작업은 초기 사용자가 겪을 저장 실패·초안 유실·증빙 누락·실적 변조·통계 비교 오류를 우선 보완한 개발 검증이다. **실제 HCP/SSO 환경의 사용자 파일럿을 완료했거나 전사 운영을 승인한 상태는 아니다.** 자동화 검증과 실제 사용자 사용성 검증을 구분한다.

구성은 두 가지다.

- 기존 `dist/index.html`: 브라우저 저장 시연. 기준 월 통계 오류를 수정했다.
- 신규 `dist/pilot.html`: React/styled-components 공용 작업공간. FastAPI에 연결해 등록·Step 실적·첨부·제출·검토·변경 승인·이력을 처리한다. 외부 정적 시연 사이트에는 공용 API가 없으므로 이 화면만 열어도 DB가 연결되지는 않는다.

## 파일럿 사용자와 업무

과제 대표자, 참여자/일반 구성원, 같은 팀장, 다른 팀장, 담당장의 입장에서 아래 시나리오를 검증한다. 데이터는 실제 업무 자료가 아닌 합성 과제와 파일이다. 로컬 개발 인증은 단일 고정 사용자이므로 여러 사람의 실제 SSO 검증을 대신하지 않는다. 권한별 API 검증은 서버가 주입한 테스트 사용자 및 서명 토큰 테스트로 실행한다.

| 문제 | 사용자 영향 | 보완 |
|---|---|---|
| 과제마다 최신 입력 월을 비교 | 오래된 실적이 정상처럼 보임 | 같은 기준 월로 집계, 이전 월 대입 금지 |
| 완료·보류·기간 종료 혼합 | 보고 대상·지연률 분모 왜곡 | 보고 대상과 제외 사유 분리 |
| 파일 관리 미구현 | 산출물과 실적을 검토할 근거 부족 | 과제/Step/보고 월 연결, 인증 다운로드, 파일 새 버전·해시·등록 이력 |
| 월별 실적은 저장만 가능 | 검토/확정 여부와 최종 보고 불명확 | 작성→제출→보완 요청 또는 확정, 제출 월 잠금 |

| 읽기 전용 사용자의 편집 시도 | 저장 단계에서 뒤늦게 권한 오류 | 화면에서 읽기 전용 표시·편집 제어, 서버 권한 재검증 유지 |

## 실행

### 자동 검증

```sh
# 저장소 루트
npm ci
npm test
npm run build

# backend 폴더
python -m pip install -r requirements-dev.lock
TEST_DATABASE_URL=<폐기-가능한-테스트-DB> python -m pytest -q
```

실제 DB 주소를 지정하지 않으면 DB 시나리오는 skip된다. 파일럿 판정에는 DB 테스트의 skip을 허용하지 않는다. GitHub Actions는 PostgreSQL 17로 전체 시나리오를 실행한다.

### 공용 작업공간 전체 실행

```sh
# 저장소 루트, backend/.env.example을 backend/.env로 복사하고 로컬 값 설정 후
# 기존 DB를 쓰지 않는 별도 파일럿 볼륨을 생성한다.
docker compose --env-file backend/.env -f deploy/pilot.compose.yaml up --build -d --wait
```

브라우저에서 `http://127.0.0.1:8080`을 연다. 루트는 `/pilot.html`로 연결되며 같은 출처 `/api`는 FastAPI로 전달된다. 파일은 별도 영속 볼륨, 메타데이터와 실적/검토는 PostgreSQL에 저장한다. 이 구성은 로컬 실행 예시이며 HCP 배포는 사내 템플릿에 맞춰야 한다.

`.env.example`의 개발 인증은 단일 고정 사용자다. 본인 제출을 직접 승인할 수 없으므로 여러 사람 검토는 실제 SSO를 붙인 검증 환경에서 수행한다. 사내 토큰 연결은 `window.ATPilotAuth.getAccessToken()`을 주입한다. 토큰을 초안 저장소나 runtime-config에 넣지 않는다.

검증용 스택의 HTTP 점검은 `python3 deploy/smoke.py`다. **폐기 가능한 합성 데이터 스택에서만 실행한다.** 과제와 파일을 실제 생성한다. 운영 환경의 점검 명령으로 사용하지 않는다.

## 저장 및 첨부의 범위

- 증빙: PDF, DOCX/XLSX/PPTX, PNG/JPG, UTF-8 TXT/CSV, 기본 20MB 제한.
- 바이너리는 영속 파일 볼륨, PostgreSQL에는 메타데이터와 연결 관계를 저장한다. HCP 오브젝트 스토리지 어댑터는 후속 연결 작업이다.
- 확장자/내용 기본 검증과 요청 크기 제한을 적용한다. 사내 악성코드 검사·문서 DRM·DLP는 실제 정책/서비스에 연결해야 한다.
- 제출·확정 월의 실적과 해당 월 증빙 추가/교체를 차단한다. 보완 요청 상태에서 수정·재제출한다.
- 제출 스냅샷의 UPDATE/DELETE를 DB에서 제한한다. DB 소유자/관리자 권한까지 통제하는 장치는 아니다.
- 현재 확정 월의 정정 재개방 절차는 제공하지 않는다. 정식 운영 전에 정정 요청·승인·새 버전 정책을 별도 구현해야 한다.
- 초안은 사용자 ID별 sessionStorage에 저장한다. 새로고침은 복원하지만 브라우저 탭 종료 이후까지 보존하는 서버 초안은 아니다. 실제 SSO 로그아웃 시 세션 초안을 정리하는 연결이 필요하다.

## 실제 사용자 파일럿 시작 전 남은 조건

다음 항목을 자동 테스트 통과와 구분해 관리한다.

1. HCP에 공용 작업공간·API·DB·영속 파일 저장소 배포, 백업/복원 확인.
2. 실제 SSO의 사용자·팀·역할 매핑, 조직도와 참여자 ID 지정/변경 기능 연결.
3. 실제 계정 2명 이상으로 공유·권한·검토·로그아웃·재로그인 확인.
4. 사내 파일 검사·보관/삭제·접근 정책 적용. 현재 무기한 파일 추가만 제공하며 보관 정책 자동화는 없다.
5. 확정 실적 정정, 연간 계획 확정/이월 정책, 조직 이동 시 과거 기준 정책 확정.
6. KPI의 정량 구조화와 실적 측정 근거. 현재 진척 통계는 KPI 성과 평가가 아니다.
7. 사내 AI·메신저 실제 연동. 현재 코드가 발송·AI 분석을 완료했다고 표시하지 않게 유지.
8. 데스크톱/좁은 화면/키보드 접근성의 실제 브라우저 시각 검증, 파일럿 사용자의 직접 관찰.

이번 실행에서는 네이티브 컴퓨터 사용 권한 대기로 실제 브라우저 시각 검증을 완료하지 못했다. React 가상 DOM 조작 검증과 Docker HTTP 통합 검증을 대신 수행했으며, 브라우저 E2E를 통과했다고 간주하지 않는다.

**출시 기준:** 위 환경·권한·데이터 보존 조건을 충족하고 실제 사용자가 주요 시나리오를 완료한 증거를 확보한 뒤 제한된 파일럿을 시작한다. 사용 가능 여부를 자동 테스트 개수만으로 결정하지 않는다.

## 2026-11-25: 월별 시간 모사와 입력 피로도 개선

- 공용 작업공간 등록을 기본 정보 → Step 정의 → 월별 목표의 3단계로 분리했다. 배경/KPI/추진 계획/공동 수행자와 Step 산출물 설정은 선택 섹션으로 접었다. 앞 단계 이동 시 입력을 보존한다.
- 실적 입력 기본 화면은 한 달만 표시한다. 연간 표는 필요할 때 펼친다. 목표와 전체 실적은 자동 계산하며, 완료한 Step의 반복 입력을 생략한다.
- 지난 월의 미입력·미제출·보완 요청을 구분해 직접 이동한다. 브라우저 시연 화면에는 실제로 제공하지 않는 제출 의무를 표시하지 않는다. 미입력은 0%로 대체하지 않는다.
- 지연 사유와 Catch Up Plan은 선택한 월의 미달 Step에만 표시한다. 직전 실적과 비교하고, 당월 증가분을 잘못 입력한 경우 서버가 누적값 오류를 안내한다.
- 실적 → 해당 월 증빙 → 저장 → 제출로 연결한다. 미저장 내용이 있으면 제출을 막는다. API 작업공간의 3단계 등록과 증빙/제출 연결은 React 가상 DOM으로 검사한다.
- P21~P23: 월 집중 화면, 누락 월 우선 선택, 다음 월 입력칸 숨김, 증빙 월 자동 연결, 완료 Step 자동 반영, 조건부 지연 사유, 단계 이동 보존.
- P24: 실제 PostgreSQL + HTTP에서 2027-12부터 2028-04까지 시계를 이동한다. 12월 누락/1월 달성·확정/2월 지연/3월 누적 미달/종료 후 12월 소급 제출을 검사한다. 미래 월, 당월 증가분 오입력, 사유·만회 계획 누락, 뒤 월보다 높은 소급값, 중복 제출, 잠긴 월 수정은 거절하고 저장 버전이 바뀌지 않는지 검증한다.
- 별도 시간 규칙 11건: 서울 자정 기준 연말·윤년 월 전환 4건, 월별 누락·소급 입력 1건, 사람의 입력 실수 6건. 테스트만 시계를 교체하며 운영용 시계 변경 API는 제공하지 않는다. DB 자체가 기록하는 저장 시각은 DB 시계로 유지한다.
- 실제 브라우저에서 월 변경이 화면의 보고 대상을 갱신하지 않는 문제를 발견해 입력 이벤트 처리로 수정했다. 시연 화면에서 11월 → 10월 이동, 누적 합계 변경, 지연 항목 조건부 표시를 직접 재검사했다.

출시 전 남은 확인: 실제 HCP·SSO·사내 메신저, 공용 API 화면의 실제 브라우저 통합 검사, 파일 보안 검사·보관 정책, 사용자 과업 완료율/입력 시간 측정. 자동 검사 통과는 운영 준비 완료를 의미하지 않는다.

### 기존 과제 호환 및 캐시 후속 검증

- P25 추가: 실제 시연 HTML의 모든 스크립트를 함께 실행하는 가상 DOM 통합 검사로 기존 단일 계획 과제의 월 집중 입력, 지연 사유, 연간 표 전환, 화면 재진입 임시저장 복원, 원본 실적 미변경, 메신저 링크의 정확한 월 선택을 검사한다. 실제 브라우저에서도 기존 단일 계획 과제에 입력 후 새로고침하여 실적·사유·만회 계획 복원을 확인했다.
