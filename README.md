# AT 과제 관리 시스템

2026-11-25 기준 구현본입니다. Step 계획·실적 화면은 React + styled-components로 구성하며, 빌드된 정적 앱도 함께 제공합니다.

## 실행 방법

1. GitHub에서 저장소를 복제하거나 ZIP을 내려받아 압축을 풀고, 터미널에서 프로젝트 폴더로 이동합니다.
2. Python 3가 설치된 환경에서 아래 명령을 실행합니다.

```sh
python3 -m http.server 8000 --directory dist
```

Windows에서 `python3` 명령이 없다면 `py -3 -m http.server 8000 --directory dist`를 사용합니다.

3. 브라우저에서 <http://localhost:8000>을 엽니다. 서버 종료는 터미널에서 Ctrl+C입니다.

`index.html`을 직접 여는 대신 localhost로 실행해 주세요. 메신저용 입력 링크는 HTTP/HTTPS 주소를 사용합니다. 별도 웹 서버에 배포할 때는 `dist` 폴더 전체를 올리고 HTTPS로 운영합니다.

## 화면 개발

Node.js 22 이상에서 의존성을 설치하고 미리보기를 실행합니다.

```sh
npm ci
npm run dev
```

배포 파일 생성은 `npm run build`, 전체 테스트는 `npm test`입니다. `dist/components.js`는 생성 파일이며 직접 편집하지 않습니다.

## 포함 기능

- 팀·PO·PM·공동 수행자, Tech·과제 분류를 포함한 등록·검색·조회
- 시작일·종료일 및 연도별 12개월 누적 목표 입력표
- Step 추가·삭제, Step별 기간·누적 목표, 비중 합계 100% 검증
- Step별 실적 입력과 전체 가중 합산, 미입력과 0% 구분, 완료 Step 실적 이월
- 별도 월별 누적 실적, 지연 사유·Catch Up Plan, 누적 지연 판정
- 지식자산 검색, 경험 카드·결과물 링크, 선행·후속·유사·결과 활용 과제 연결맵
- 운영 인박스, 관리 대시보드, 과제별 규칙 기반 Summary
- 정보·담당자·일정·목표 변경 승인·반려·철회와 최초 계획 비교
- 승인 시 최신 실적 보존, 전체 활동 이력·내보내기, 보관·복구 승인
- 실적 요청 대상·기한·메시지 미리보기, 중복 방지와 요청 이력
- 메신저 연동 요청 파일 준비 및 대상 월 실적 입력 링크

## 데이터와 연동 상태

현재는 브라우저 저장 기반 시연입니다. 브라우저·주소·포트가 바뀌면 과제 저장 공간도 달라집니다.

이 ZIP에는 앱에 기본 포함된 가상 예시 3건이 들어 있습니다. 기존 배포 사이트의 현재 브라우저에 등록한 과제·승인·실적·요청 데이터는 포함되어 있지 않습니다.

SSO 로그인, 조직도, 서버 권한 검증, 공용 데이터베이스, 사내 AI, 메신저 실제 발송은 연결 전입니다. 이름·역할을 입력하는 승인 기능은 검토 흐름의 시연이며 실제 계정 권한을 부여하지 않습니다. AI Summary는 규칙 기반 분석입니다. 메신저 요청 준비와 파일 생성은 발송 완료로 처리하지 않습니다.

서버 연동 규격은 `docs/messenger-integration.md`를 참고해 주세요.

## 구성

- `src/main.jsx`: React Step 목표 편집·실적 보고·상세 컴포넌트
- `src/ui.jsx`: styled-components 공통 입력·표·카드·버튼과 ThemeProvider 테마
- `scripts/`: 빌드 및 로컬 개발 서버
- `dist/`: 기존 앱 소스와 실행용 번들. 기존 목록·승인 화면은 점진 전환을 위해 유지합니다.
- `tests/`: 계산·승인·요청·저장 흐름을 검증하는 테스트 파일
- `docs/messenger-integration.md`: 사내 메신저 연동 규격 초안
- `VERSION.txt`: 소스 버전 정보

## 검증

Node.js 22 환경에서 프로젝트 폴더에서 실행합니다. 추가 패키지는 필요 없습니다. GitHub에서도 push와 PR마다 같은 검증을 실행합니다.

```sh
node --test
```

기존 계산·승인·요청 흐름의 자동 검증을 유지합니다. 승인 전 원본 유지, 승인 대기 중 실적 보존, 자기 승인 제한, 보관·복구 및 요청 중복 방지도 실제 화면에서 점검했습니다.

## Step 계산과 기존 데이터

- 화면의 Step 목표·실적 입력 최대값은 해당 Step 비중입니다. 비중 40%인 Step은 0~40%를 입력하고 마지막 목표는 40%입니다. 전체 목표·실적은 화면에 표시된 Step별 기여도를 합산합니다. 내부 저장은 기존 Step 완료 비율 0~100을 유지합니다.
- Step 시작 전 목표/실적 기여는 0입니다. Step 종료 후 목표는 해당 비중이며, 미완료 실적은 과제 종료 월까지 계속 입력할 수 있습니다.
- 시작한 Step 중 실적이 하나라도 없으면 해당 월의 전체 실적은 미입력입니다. 이전에 해당 비중만큼 완료한 Step은 이후 월로 이월합니다.
- Step 지연 사유와 Catch Up Plan을 입력합니다. 전체 지연은 가중 누적 목표/실적의 차이로 판정합니다.
- 기존 단일 계획은 유지됩니다. 수정 화면에서 ‘Step별 계획으로 전환’을 선택하고 승인받으면 전환됩니다. 과거 전체 실적은 별도 보존하고 Step 실적은 임의로 나누지 않습니다.
- Step 이름·기간·비중·목표 변경은 승인 대상입니다. 승인 시 최신 실적을 보존하고 제거된 Step의 실적도 기록에 남깁니다.

화면 상태별 스타일은 [styled-components 공식 문서](https://styled-components.com/docs/basics)의 컴포넌트 속성과 공통 테마 방식을 사용합니다. 전체 앱을 React로 전면 전환한 상태는 아니며, 이번 신규 Step 화면부터 적용한 구조입니다.

## PostgreSQL 프레임

[설치 및 API 설명](docs/postgresql-setup.md)에 DB 스키마, 로컬 실행, 인증 연결 지점, 데이터 단위와 테스트 방법을 정리했습니다. 배포 화면은 브라우저 저장을 사용하며, PostgreSQL API와 연결할 클라이언트를 별도로 제공합니다.

## 분리된 FastAPI 백엔드

신규 백엔드 개발은 [`backend/`](backend/README.md)에서 진행합니다. Python 3.12+, FastAPI, PostgreSQL 연결 풀, 독립 SQL 마이그레이션, 과제·실적·승인·감사 이력 API, OIDC JWT 검증 연결부, Docker 실행 및 별도 CI를 제공합니다. `backend/` 폴더만 복사해 독립 실행할 수 있으며 Node.js와 프런트엔드 소스에 의존하지 않습니다. 기존 `server/`는 이전 Node.js 프레임 참고용입니다. API 개발 시 기본 대상은 FastAPI입니다.

HCP 이전을 맡을 사내 에이전트용 [Docker·Jenkins 마이그레이션 인수인계 노트](backend/HCP_MIGRATION_NOTES.md)를 제공합니다. HCP 원본 템플릿에서 확인할 사항과 현재 코드의 연결 작업을 구분해 기록했습니다.

## 공용 작업공간과 파일럿 검증

신규 `dist/pilot.html`은 공용 FastAPI에 연결해 과제 등록, Step 실적, 첨부 증빙, 제출·검토·확정, 변경 승인·이력을 처리하는 React/styled-components 작업공간입니다. 기존 `index.html`은 브라우저 저장 시연으로 유지합니다. 전체 실행은 `deploy/pilot.compose.yaml`, 시나리오·발견 문제·출시 전 조건은 [파일럿 검증 노트](docs/pilot-validation.md)에 정리했습니다. 외부 정적 시연 사이트에 운영 DB/SSO가 자동 연결된 상태는 아닙니다.
